# For each change

1. Create a new feature branch, PR and then make the changes at each step.
2. Once a step is completed give a list of tests that should be perform manually to confirm the changes are working.
3. Once  confirmation is received merge the PR and the branch to the dev branch.
4. Change on those features that have been requested explicitly.
5. No other change must be done without informing and conformation
6. Before asking for confirmation display a preview of the change





# Skill based development

1. For every new change evaluate if this can be wrapped into a new skill or added to an existing skill and solicit confirmation



\# GitHub Issues

1. Any defect identified should be added as an issue in the GitHub Issues list





\# UI Creation

1. When a new UI element is needed add it as a component (for e.g. text box) and use that for standardisation.



\# Documentation

1. After each feature addition/update add it to a running features document. Use clear layman understandable language.
